## ✨ 功能

### 📥 收集论文

| | |
|---|---|
| 🔗 **arXiv 一键入库** | 粘贴 arXiv 链接或编号（如 `2401.12345`），自动下载 PDF 并抽取全文。 |
| 📤 **本地 PDF 上传** | 直接把电脑里的 PDF 拖进来；按文件内容指纹去重，重复上传会提示已在库中。 |
| 🧲 **引文挖掘** | 读完这篇论文的 Related Work 与参考文献，按其中提到的标题去 arXiv 模糊检索；标题匹配度低于 0.7 的直接剔除，再用摘要判定与当前论文的相关度（不做全文总结），只保留相关度高于 0.6 的候选供你筛选，强相关的可一键加入详细阅读。引用里提到多少就处理多少，不设数量上限。 |

### 📖 阅读与翻译

| | |
|---|---|
| 🖨 **内置 PDF 阅读器** | 本地 PDF.js 渲染，带真实文字层：滚轮 / 触摸板两指顺滑翻页，捏合或按住 ⌘/Ctrl 滚轮以光标为锚点缩放，另有适应宽度、精确倍率、跳页、旋转。 |
| 🖍 **划词翻译** | 选中任意一句或一个词，点浮出的「翻译」，译文就出现在阅读器右侧的译文栏里，可连续翻多段并回看，也能一键复制。 |
| 🔎 **全文检索** | 在 PDF 里查找关键词，显示命中总数并逐处跳转定位。 |
| ⧉ **选中即复制** | 文字层是真实文本，复制术语、符号、段落不再需要 OCR 或截图。 |
| 📏 **整篇全文入库** | 抽取全文不设字符上限，长论文的结尾、附录与参考文献同样能问答、能按页码引用。 |
| 🌐 **中英界面** | 界面可整体切换中文 / English，译文跟随应用的输出语言设置。 |

### 🧠 理解与整理

| | |
|---|---|
| 💬 **全文问答** | 就当前论文提问，全文自动作为上下文并标注页码；长任务可随时终止，已生成内容保留。 |
| 🧩 **四个独立 AI 动作** | 快速总结 / 自动分类 / 深度精读 / 论文关系，各自单独触发、单独重跑，按钮上直接显示这一步已有的结果，不必一次跑完整套。 |
| 📝 **阅读笔记** | 快速总结与深度精读都保留历史版本，可复制、可导出 Markdown、可开独立窗口专注阅读。 |
| 🌳 **方向树** | 让模型把论文归入唯一分类方向，自动长出层级文件夹；也可以自己建子文件夹、手动移动归类。 |
| 🕸 **关系图谱** | 流程图式的有向图：分层排布，箭头带关系类型与证据强度，悬停高亮相关边，点节点直接打开那篇论文。单篇论文看它自己的关系邻域，方向文件夹看整张子图。 |
| 📄 **文件夹综述** | 把一个文件夹下的所有论文汇总成一份综述报告，分批取证、可续跑、历史可回看。 |

> 所有 AI 能力都由**你自己配置的模型**驱动（兼容 OpenAI Chat Completions 接口的服务均可），不注册账号、不需要服务器。

## 🚀 使用方式

### 方式一：下载桌面应用（推荐）

到 **[Releases](https://github.com/HypherX/ArxivReader/releases)** 下载对应平台的压缩包：

| 平台 | 文件 |
|---|---|
| 🍎 Apple Silicon（M 系列） | `ArxivReader-macOS-arm64.zip` |

- **macOS**：解压后把 `ArxivReader.app` 拖进「应用程序」，双击打开。若提示「无法验证开发者」，到 **系统设置 → 隐私与安全性** 点「仍要打开」即可，无需关闭系统安全功能。
- **Windows**：解压后保留文件夹内全部文件，双击 `ArxivReader.exe`。

> 构建包未做签名与公证，首次启动的系统提示属于正常现象。每个压缩包都附带 `.sha256` 校验文件。
> 目前我们只构建了 M 系列芯片的 Mac 版本，其他平台可以自行构建。

### 方式二：从源码运行（浏览器打开）

需要 Python 3.12 或更新版本：

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 启动服务，然后浏览器打开 http://127.0.0.1:8765
python -m uvicorn app.main:app --host 127.0.0.1 --port 8765

# 或者：开一个桌面窗口（需要 pywebview，见 requirements-build.txt）
python desktop.py
```

## ⚙️ 首次配置模型

首次启动会自动打开「设置」，填三项即可：

1. **Base URL** — 模型服务的 API 地址（兼容 OpenAI Chat Completions 接口的都行）。
2. **API Key** — 你的密钥。
3. **模型** — 模型名称，比如 `gpt-4o`、`deepseek-chat`。

点「测试连接」确认能用（会真实调用一次模型），再点「保存」。
**不配模型也能用**：管理论文、阅读 PDF、划词复制都照常，只是 AI 相关功能不可用。

## 🗂 论文放在哪

新加入的论文默认只属于 **「全部论文」** 这个总目录——不会被自动塞进任何子文件夹。之后你可以：

- 点 **🗂 自动分类**，让模型把它归入方向树里的某个方向（同时生成对应的方向文件夹）；
- 或自己建子文件夹，用 **📁 移动** 放进去，也可以再移回「全部论文」。

「全部论文」始终展示库里的每一篇；选中某个文件夹时，会连同它的所有子文件夹一起统计。

## 📁 数据存在哪

| 运行方式 | 数据目录 |
|---|---|
| 桌面应用（macOS） | `~/Library/Application Support/ArxivReader/data/` |
| 桌面应用（Windows） | `%LOCALAPPDATA%/ArxivReader/data/` |
| 源码运行 | 项目目录下的 `data/` |

PDF、数据库、笔记全在这个目录里，**备份 = 复制整个目录**（备份前先关闭应用），换电脑同理。

两点需要知道：

- API Key 以明文存在本地数据库里，请不要把整个 `data/` 目录分享给别人。
- 「本地保存」不等于「完全离线」：下载 arXiv 论文需要联网；AI 功能会把论文内容发给你配置的模型服务商并产生费用，数据政策以服务商为准。

## ❓ 常见问题

<details>
<summary><b>上传的 PDF 没有作者、摘要信息？</b></summary>
本地 PDF 没有 arXiv 元数据，标题会取 PDF 自带的标题或文件名，可以直接改名。AI 问答和总结不受影响（全文已抽取）。
</details>

<details>
<summary><b>扫描版 PDF 无法提问？</b></summary>
扫描件没有文字层，抽不出文本，需要先用 OCR 工具处理。这类 PDF 依然能正常阅读，只是 AI 功能没有文本可用。
</details>

<details>
<summary><b>译文会重复花钱吗？</b></summary>
不会。译文按原文哈希缓存在本地资料库里，同一段第二次点开直接读缓存，不再调用模型。
</details>

<details>
<summary><b>长任务跑一半想停？</b></summary>
所有 AI 任务都能随时终止，已经生成的部分会保留并落库，不会白烧 token。
</details>

<details>
<summary><b>Mac 提示应用已损坏 / 无法打开？</b></summary>
这是未签名应用的正常提示，按「使用方式」里的说明在「隐私与安全性」中允许即可。
</details>
