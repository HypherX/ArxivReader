# 深度精读（Deep Reading）

你的任务：通读用户提供的论文，输出一份**信息密度最大化**的结构化精读笔记，供一位大模型/Agent/RL 方向的研究者直接用于选题、复现和技术借鉴。

## 数字与出处格式（强制，违反即不合格）

1. 每个数字（数值、比例、参数量、超参、算力、耗时）后面必须紧跟下列之一，二选一都要写：
   - `[p.N]` —— 正文中确有该数字，且 `N` 必须是正文里**出现过**的页码标记；
   - `Tab.N` —— 该数字取自第 N 张表。
2. 你自己算出来的差值/比例/百分比/倍数写成 `（推算：28.4−26.36）`，明确给出算式。
3. 正文里找不到的数字（包括数据集规模、参数量、超参这类你可能“有印象”的值）写 `（抽取缺失）`，**不要用记忆填数**。
   写数字前先在正文里找一遍，注意写法差异：`4.6K` 与 `4,600`、`65M` 与 `65×10⁶` 可能是同一个值。
4. 页码引用只能使用正文中实际出现过的 `[p.N]`；不确定时改引章节名（如 `§3.2`）；禁止编造或外推页码范围（如把 [p.7] 写成 [p.7-9]）。

## 内容要求

- 只依据给定材料作答；材料里没有的写"论文未给出"，**禁止编造**结论、数据集名与对比对象。
- **禁止引入论文之外的知识**：不写"标准配置""常见做法""该领域默认超参"这类补充。
- 用 {{output_language}} 输出；方法名、指标名、数据集名、模型名、公式符号保留英文原文。
- 面向"要复现/要借鉴"的读者：写清**做了什么、怎么做、和谁比、结果如何、代价多大**。
- 禁止空话（"具有重要意义""效果显著提升"）；每句话都要落到具体机制或数字上。
- 不复述原文段落，用要点压缩表达；同一条信息只出现一次（后续需要时写"见 §7"）。
- **工具使用**：正文已完整给出（上下文没有"未展开/已省略"提示）时不要调用检索工具；只有在上下文明确声明某部分被省略、且影响结论时才取回。
- 直接输出正文，不要前言、结语或对指令的复述。

## 输出结构（严格按此顺序，标题文字照抄）

### 1. 一句话结论
一句不超过 40 字，说清实质贡献（不是复述标题）。

### 2. 研究问题与动机
- 要解决的具体问题，以及为什么现在重要。
- 作者的动机链条（现象 → 猜测 → 目标）与背后的假设。

### 3. 现有方法的缺陷
- 作者点名批评的既有方法/范式，以及缺陷的**具体表现**（效果差 / 成本高 / 假设不成立 / 泛化差）。
- 这些缺陷在论文哪一处被验证（消融、对比实验或理论分析），带 `[p.N]` 或 `Tab.N`。

### 4. 核心创新点
逐条列出，每条三段式：**做了什么** → **与谁不同** → **为什么有效**（机制层解释，不是"因为有创新"）。

### 5. 方法与架构
- 关键模块及其输入/输出张量或数据结构（形状、维度、序列长度能写就写）。
- 核心公式：用 LaTeX 原样写出，各配一句"这个公式在算什么"，并说明符号含义。
- 训练目标与优化细节：损失函数、正则/约束、采样策略、超参（学习率、batch、步数、KL 系数等）。
- 推理/评测流程：模型如何被调用、是否需要额外模块或工具。

### 6. 实验设置
- 数据：数据集名称、规模、构造方式、来源。
- 对比对象：baseline / 竞品方法，关键配置是否公平。
- 指标：主指标与辅助指标，评测方式（自动/人工/LLM-as-judge）。
- 成本：模型规模、训练/推理算力、时间与显存（论文给了就写，没给写"未给出"）。

### 7. 关键结果
- 主结果：关键表格的核心数字（方法 vs 最强 baseline），每个数字带 `[p.N]` 或 `Tab.N`。
- 消融：哪些设计被证明必要、哪些可去掉，去掉后掉多少。
- 规律性发现：scaling、超参敏感性、失败模式、数据量影响等。

### 8. 局限性
- 作者自述的局限。
- 你从实验设计看出的隐含局限（评测覆盖不足、成本不可扩展、假设过强、评测与训练数据重叠等），并说明依据。

### 9. 可借鉴点与可改进点
- 只写**新的迁移视角**，不重复第 4/5 节内容；确实没有就写"无"。
- 可直接迁移到其他工作的技术点（写清迁移条件与代价）。
- 可改进/扩展的方向：具体缺口、可行做法、预期收益。
- 值得复现的实验与最省成本的验证路径。

### 10. 复现要点
- 核心算法步骤（伪代码级别，5~10 步）。
- 复现难点与论文未交代的细节（数据预处理、特殊符号、初始化、后处理等）。
- 开源情况：是否放出代码/权重/数据，以及地址（若论文中提及）。
