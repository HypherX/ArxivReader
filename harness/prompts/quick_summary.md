# 快速总结（Quick Summary）

你的任务：快速判断一篇论文**值不值得精读**，只输出总结层的信息——核心 Insight、贡献、结论。细节（完整公式推导、逐表数字、超参配置、复现步骤）留给"深度精读"，这里不需要。

这份摘要还要被后续流程用来**把论文归入全局方向树**，因此"解决了什么"与"未来展望"两行必须具体到可判断领域（不要写"提升了效果"这类无法归类的表述）。

## 内容要求

- 只依据给定材料作答；材料中没有的信息写"摘要未含"，**不要推测**，不要补全你没看到的内容，也不要补充论文之外的知识。
- 用 {{output_language}} 输出；方法名/指标名/数据集名保留英文原文。
- **不设字数上限**，但每一行只讲一件事：不要复述摘要原句，不要罗列细节（超参、逐表数字、附录内容）。
- 写"结论层"而不是"过程层"：与其写"提出了 X 模块 + 做了三组实验"，不如写"X 用更低的成本解决了 Y 的什么缺陷"。
- "做法"必须写到机制（改了什么、怎么算），不能只写"提出了一个新框架"。
- "关键数字"必须是材料里出现过的数字，并带对比对象；材料里没有就写"摘要未含"——**不要用记忆补数**。
- "实质差异"要给出真实区别（机制不同 / 假设更弱 / 成本更低），而不是"效果更好"。
- "判断"必须明确表态并给理由；如果这篇论文对做 LLM/Agent/RL 的研究者只有边缘价值，就直说。

## 输出结构（严格照抄标签，按顺序输出：TL;DR 一行 + 6 行要点）

TL;DR: <一句话说清它做了什么、解决什么问题>

- 解决了什么: <它针对的具体痛点 + 这篇工作把该痛点解决到什么程度（这是后续归类到方向树的关键信息）>
- 做法: <核心机制（改了什么、怎么算），可含关键公式符号或模块名>
- 关键数字: <最能说明问题的 1~3 个数值及其口径；没有则写 摘要未含>
- 实质差异: <与最接近的已有工作的真实区别>
- 未来展望: <作者指出的局限性 + 未来研究方向；论文没写就写"论文未给出">
- 判断: <值得精读 / 只需看 Methods / 可跳过> —— <一句理由，说明对哪类研究者有用>
